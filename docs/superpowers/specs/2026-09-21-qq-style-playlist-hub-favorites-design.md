# QQ 音乐式歌单导航、Plex 歌单管理与二态收藏设计

## 目标

在不改动当前视觉主题的前提下，把“我的歌单”重组为接近 QQ 音乐桌面端的信息架构：左侧只保留少量稳定入口，自建歌单直接列出，算法与曲库整理结果进入各自的卡片首页。同时修复生产环境已经复现的播放与拖动故障，接入 Plex/Plexamp 原生歌单，并提供一个简单的二态爱心收藏。

本次不开发皮肤切换器，不复制 QQ 音乐的商标、图片或专有素材。布局继续使用语义化 CSS 变量，确保后续增加多套皮肤时不需要重写页面结构与业务逻辑。

## 已确认需求

- 左侧顶部固定两个入口：“智能歌单”和“曲库整理”。
- “智能歌单”内容区用卡片展示每日推荐、每周常听、时光胶囊、最近新增、自定义智能歌单和“我的最爱”。
- “曲库整理”内容区用卡片展示由当前 Plex 曲库与 QQ 音乐参考数据匹配生成的分类歌单。
- 左侧下方直接列出“自建歌单”，包括外部导入歌单以及 Plex/Plexamp 创建的歌单。
- 自建歌单不能再因为未被本应用登记而从左侧消失。
- 普通歌单可重命名、添加歌曲、移除歌曲和删除；删除只删除歌单，不删除音乐文件。
- 每首歌曲只显示一个空心/实心爱心，不显示星级或评分选择器。
- 喜欢状态与 Plex 同步，并自动汇总到“我的最爱”。
- 移除没有独立功能的“搜索全库添加”按钮；顶部全库搜索继续承担查找、播放和加入歌单功能。
- 修复每日推荐无法播放、拖动进度后无法继续播放以及弹窗关闭叉号默认不可见的问题。

## 已确认根因与生产证据

### 左侧缺少 Plex 歌单

当前 `playlist_rows()` 明确只读取本应用本地登记的 `daily`、`smart`、`category` 和 `external` 四类歌单，不访问 Plex 的歌单列表。因此 Plex/Plexamp 新建歌单不会进入左侧。

生产环境当前两个已启用曲库分别为“音乐”和“经典音乐”，Plex 对对应账户返回 28 个音乐歌单，其中 17 个为智能歌单、11 个为普通歌单；当前页面只显示本应用登记的子集。两个曲库使用同一 Plex 账户时会得到同一份账户级歌单列表，前端和后端必须按 Plex 歌单 ID 去重，不能因为曲库档案不同重复显示。

### 搜索与歌单播放链路不一致

搜索结果通过曲库音频路由直接验证曲目是否属于当前曲库；歌单曲目播放则先重新读取整张 Plex 歌单、核对标题和所有权标记，再打开相同曲目的音频。播放阶段重复做歌单级网络读取没有增加曲目访问权限，因为用户已经能够通过全库搜索播放当前曲库任意歌曲，却增加了失败点和延迟。

设计上统一所有本地曲目的音频与封面读取入口：播放授权只验证登录档案、当前曲库和曲目可用性；歌单详情与编辑仍执行对应的歌单权限和成员校验。队列上下文只负责上一首、下一首和当前高亮，不再决定音频代理路由。

### FLAC 拖动失败

生产环境对同一首 FLAC 的现有转码请求测试结果为：`offset=0` 返回 HTTP 200，`offset=30` 返回 HTTP 400。加入 Plex 文档要求的客户端标识、会话标识与快速拖动参数后仍返回 HTTP 400。因此不能继续依赖“重新创建带 offset 的 MP3 转码流”实现拖动。

当前目标浏览器原生支持 FLAC。浏览器可播放的 FLAC、MP3、AAC/M4A 使用 Plex 媒体 Part 的直接代理，并保留 `Range`、`Content-Range`、`Content-Length` 和 `Accept-Ranges`；拖动交给 `<audio>` 的原生字节范围请求。只有浏览器确实不支持的格式才走转码，并且未知时长的转码流不承诺任意位置拖动，避免再次发送已知失败的 offset 请求。

## 推荐的信息架构

### 左侧导航

从上到下固定为：

1. 当前 Plex 用户与曲库选择器。
2. “智能歌单”固定入口。
3. “曲库整理”固定入口。
4. “自建歌单”标题、刷新按钮和可滚动歌单列表。
5. 设置、运行状态等现有工具入口保持独立，不混入歌单分类。

“智能歌单”和“曲库整理”是内容首页，不是可删除的实际 Plex 歌单。左侧不再展开它们下面的几十个子歌单，也不再使用“日、智、类、外”单字图标区分来源。

自建歌单列表按 Plex 返回顺序显示，标题过长时单行省略。来源、普通/智能类型、歌曲数量和可编辑能力在主内容区展示，不用弱化可读性的前缀或单字徽标塞进左栏。

### 内容区

- 打开“智能歌单”时显示响应式卡片网格。卡片包含标题、简短说明、歌曲数量和播放入口；点击卡片进入现有歌曲表格详情。
- 打开“曲库整理”时显示分类歌单卡片网格；未生成的分类不伪装成可播放歌单，而是明确显示“尚未生成”并进入对应整理工具。
- 打开自建歌单时直接显示歌曲表格、播放全部、重命名、删除及适用的编辑操作。
- 进入搜索、设置、运行状态或创建工具时继续复用固定工作台，不销毁底部播放器。
- 主题仍使用现有浅色变量。卡片、导航和播放器不得写死为深色，后续皮肤只替换变量与可选背景资源。

## 歌单来源、去重与能力模型

后端列表由两部分合并：

1. 本应用登记的每日、智能、分类和外部歌单。
2. Plex 当前账户返回的全部音乐歌单。

以 Plex `ratingKey` 为稳定去重键。本应用登记的歌单若在 Plex 列表中出现，只保留本应用记录，并携带管理类型；其余 Plex 歌单作为原生自建歌单。API 每行提供明确能力，而不是让前端根据 `kind` 猜测：

- `section`: `smart`、`library` 或 `custom`
- `source`: `assistant`、`external` 或 `plex`
- `smart`: 是否为 Plex 动态智能歌单
- `can_play`
- `can_rename`
- `can_add_tracks`
- `can_remove_tracks`
- `can_delete`
- `manage_url`

普通 Plex 歌单允许重命名、添加、移除和删除。Plex 智能歌单成员由规则动态计算，Plex API 不支持逐首手工增删；本次允许查看、播放、重命名和删除，不伪造“添加成功”或“移除成功”。智能规则编辑器不在本次范围内。

本应用算法歌单的手工加入与移除继续写入现有持久化覆盖规则，后续再生成时尊重用户调整。删除算法歌单继续走现有所有权与指纹保护。删除原生 Plex 歌单需要重新读取目标 ID 与标题、显示不可恢复警告并再次确认；任何删除都不得调用媒体文件删除接口。

Plex 歌单列表在进入首页、切换档案和用户点击刷新时读取；不增加后台轮询。网络失败时保留本应用歌单与最近一次成功的只读列表，显示可重试状态，不能用空结果覆盖正常列表。

## 二态爱心与“我的最爱”

界面只暴露一个二态爱心：

- `user_rating >= 8` 显示实心爱心。
- 未评分或 `user_rating < 8` 显示空心爱心。
- 点亮爱心通过 Plex `PUT /:/rate` 写入 10 分。
- 取消爱心写入 0 分。

用户永远不需要选择一到五星。已有四星、五星歌曲自动显示为实心，不改写其评分，直到用户主动取消或再次喜欢。

爱心出现在歌曲行和底部播放器；两处状态共享同一当前曲目模型。操作采用乐观视觉反馈，但只有 Plex 返回成功并回读评分一致后才提交本地目录值；失败则恢复旧状态并显示播放器内或页面内错误，不留下假喜欢。

“我的最爱”是“智能歌单”中的固定虚拟歌单，由当前曲库目录中 `user_rating >= 8` 的可用歌曲实时派生，不另建或持续覆盖一个 Plex 普通歌单。因为喜欢本身写入 Plex，Plex/Plexamp 与网页看到的是同一评分；本网页的“我的最爱”无需额外同步任务。

喜欢和取消喜欢同时记录为现有推荐学习系统的明确正向/撤销信号，但不关闭播放完成、跳过、近期疲劳等自动学习。爱心是用户明确表达，不是算法学习的唯一来源。

## 搜索与编辑

歌单详情页移除“搜索全库添加”按钮及其六秒提示。顶部搜索框始终搜索当前曲库，结果行继续提供“添加到歌单”。

添加目标只列出 `can_add_tracks=true` 的歌单；动态 Plex 智能歌单不会出现在目标选择框。若当前没有可添加的普通歌单，弹窗不打开，直接说明需要先创建普通歌单。

自建普通歌单的重命名、添加、移除均执行写前读取和写后回读。原生 Plex 歌单不要求本应用所有权标记，但必须属于当前认证账户实际返回的音乐歌单集合；请求不能仅凭浏览器传入的 ID 操作任意 Plex 对象。

## 播放器修复

- 所有歌单和搜索结果统一使用曲库级音频、封面路由。
- 播放路由仍要求有效登录会话、启用档案、数字曲目 ID、当前曲库目录存在且 `available=true`。
- FLAC 加入直接播放白名单，保留上游 Range 语义。
- 已知时长且浏览器给出有限 `audio.duration` 时，只设置 `audio.currentTime`，不替换媒体地址。
- 不再为转码流拼接 `offset` 查询参数；若浏览器无法原生定位，进度条保持只读或回到已确认可播放的位置，并给出明确提示。
- 播放失败自动重试仍最多一次，旧媒体事件不能覆盖新曲目状态。
- 每日推荐、Plex 原生歌单与搜索结果使用相同回归测试曲目验证首播、暂停、续播、下一首和拖动。

## 关闭按钮与可访问性

添加到歌单弹窗的关闭按钮显式设置默认文字色、悬停色、焦点轮廓和足够点击区域，不能依赖浏览器默认颜色或只在 hover 时可见。

卡片、歌单行、爱心和所有管理按钮均支持键盘操作与明确的 `aria-label`。关键操作不能只在鼠标悬停时出现；移动端的移除、爱心和菜单入口必须始终可发现。

## 错误处理与安全边界

- 列表读取失败不清空已加载数据；详情读取失败不误切到另一张同名歌单。
- 评分、重命名、增删歌曲和删除歌单均按当前档案固定执行，切换档案后旧响应必须失效。
- 所有写操作序列化，并在写后回读确认目标 ID、标题或评分结果。
- 普通 Plex 歌单删除前显示歌单名和“不会删除音乐文件”；智能歌单同样明确删除的是规则与歌单对象。
- 不暴露 Plex Token、服务器内部 URL、媒体文件路径或认证 Cookie。
- 不为展示原生歌单降低现有应用托管歌单的所有权与指纹保护。

## 测试策略

按测试驱动方式先增加失败测试，再修改实现：

### 后端单元测试

- 合并本应用与 Plex 歌单、按 Plex ID 去重，并正确分配三个 section。
- 同一账户下两个曲库档案不会在单个档案页面重复同一 Plex 歌单。
- 普通与智能 Plex 歌单能力字段准确；智能歌单拒绝逐首增删。
- 原生歌单详情只接受当前账户列出的音乐歌单 ID。
- 原生普通歌单重命名、增删、删除均写后回读；跨档案或伪造 ID 被拒绝。
- “我的最爱”仅返回当前曲库中可用且评分至少 8 的歌曲。
- 爱心写入 10/0，回读不一致时不更新本地目录。
- FLAC 走直接 Part 路由并透传 Range；不再发送非零转码 offset。
- 所有歌单播放最终使用与全库搜索相同的曲库曲目授权。

### 前端模块测试

- 左侧只出现两个固定入口，自建歌单不含本应用智能/分类歌单的重复项。
- 两个固定入口打开卡片首页，卡片再打开详情。
- 关闭按钮在默认、悬停和键盘聚焦状态均可见。
- 只渲染一个二态爱心，不出现星级控件。
- 爱心在歌曲行和当前播放器之间同步，失败时回滚。
- 搜索添加目标过滤掉不可逐首编辑的智能歌单。
- 移除“搜索全库添加”按钮与对应聚焦提示。
- 切换档案时取消旧列表、旧评分和旧播放请求。

### 集成与生产前验证

- 全量现有测试通过。
- 在至少一首生产 FLAC 上验证首播与拖动后继续播放。
- 同一首歌分别从搜索、每日推荐、“我的最爱”和 Plex 原生歌单播放。
- 实际 Plex/Plexamp 新建普通歌单刷新后出现；测试重命名、添加、移除，再由 Plex/Plexamp 回读一致。
- 使用专门测试歌单验证删除确认；确认音乐文件仍存在。
- 点亮和取消爱心后，Plex/Plexamp 与网页状态一致，“我的最爱”即时增删。
- 桌面宽度和移动抽屉下均验证导航、卡片、播放器与管理菜单。

## 非目标

- 本次不实现深色、壁纸或多皮肤切换器。
- 本次不复制 QQ 音乐的图片、品牌、推荐内容或视觉素材。
- 本次不实现 Plex 智能歌单规则编辑器。
- 本次不删除或修改任何音乐文件。
- 本次不把算法学习简化为只看爱心，也不暴露复杂评分界面。

## 验收标准

- 左侧稳定保持“智能歌单”“曲库整理”和自建歌单三段结构，即使有几十张算法歌单也不膨胀。
- 生产环境 28 个 Plex 音乐歌单能按去重与能力规则正确呈现。
- 新建 Plex/Plexamp 歌单无需重新导入，手动刷新即可看到。
- 每日推荐、搜索、我的最爱与原生歌单都能播放同一首可用曲目。
- FLAC 拖动后继续播放，不再触发已知的非零 offset HTTP 400 请求。
- 所有歌曲只出现一个空心/实心爱心，喜欢状态与 Plex 一致。
- 删除任何歌单都不删除音乐文件；不可逐首编辑的智能歌单不会展示虚假操作。
- 关闭叉号在不悬停时清晰可见。
- 全量自动化测试与生产前针对性验证通过后才允许发布。
