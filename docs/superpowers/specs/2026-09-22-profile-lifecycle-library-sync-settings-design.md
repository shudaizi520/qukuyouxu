# 用户档案生命周期、同库歌单同步与设置页设计

日期：2026-09-22
状态：待用户审阅；本文只规定设计，不授权代码发布或部署。

## 目标与边界

一个业务档案由 Plex 用户 ID、服务器 machine identifier、音乐库 ID 共同确定。同一 Plex 用户的不同曲库是互不影响的档案。添加档案时为该档案建立个人推荐，并接收主账户已完成的同库分类结果；移除档案时清除该档案及本程序为它创建的 Plex 歌单。主账户管理曲库分类，子账户只接收结果。整个设置页需要清楚、整齐、专业，不堆重复标题、小字、提示和开关。

本轮不删除音乐文件，不编辑或删除用户在 Plex 自建的歌单，不把一个曲库的整理结果推给另一个曲库，也不把一个人的播放习惯用于另一个人的推荐。旧讨论文档中“归档保留歌单”“重新添加恢复旧档案”“全局每日/智能开关控制全部账户”与本文冲突的部分，以本文为准。连接 Plex、导入外部歌单、播放和其他独立功能保持原有业务边界。

## 选定方法

主账户分类变更后立即向同库档案推送；失败的目标独立重试。仅定时扫描会延迟删除和重建；只推送一次则可能因 Plex 暂时失败留下旧副本。后台可以做低频核对来补齐漏掉的目标，但它只核对本程序记录的来源与副本，不重新整理曲库、不产生额外用户开关。

用户初始化同样只针对新增档案。添加请求保存一个完整、独立的档案后启动其后台准备工作，不阻塞界面等待所有 Plex 写入；已有档案不因此重新生成或发布。操作必须幂等，刷新页面或重复请求不得创建同一业务身份的第二个档案或重复歌单。

## 档案身份和设置

- 业务身份为 `(Plex 用户类型与 ID, 服务器 machine identifier, 曲库 ID)`；所有任务、歌单记录、历史、开关和错误都按此身份作用域保存。显示名称只用于阅读，不作为身份或删除依据。
- 设置页的“添加用户”按“选择 Plex 用户 → 选择该用户有权访问的音乐库 → 添加”完成。它不负责切换当前档案；当前档案只在左上角选择。
- 新档案只继承经验证的连接凭据和服务器身份，不恢复以前移除档案的托管歌单 ID、学习历史、缓存、错误或开关。相同且仍存在的档案再次添加返回现有档案，不重复创建。
- 新档案的三个开关默认开启：`播放学习`、`每日推荐`、`智能歌单`。三个开关互不联动。智能歌单开关统一控制每周常听、时光胶囊、最近新增。自定义精选仍按手动操作；曲库整理没有子账户开关。
- 关闭每日或智能开关只停止对应自动更新，保留已发布歌单及其歌曲。关闭播放学习只停止该档案后续行为学习，不自动关闭推荐开关，也不清除既有历史。再次开启后按该档案下一个可执行时段继续。

## 新档案的首次准备

添加成功后立即为该档案尝试生成并发布每日推荐、每周常听、时光胶囊、最近新增。每张歌单只使用该档案自己的可验证播放、收藏和曲库数据；数据不足时保留待生成状态，不伪造偏好、不发布空歌单。后续有足够数据时由正常计划补建。

曲库整理在添加档案时**绝不启动扫描或重新分类**。若主账户已为同一服务器、同一曲库发布分类结果，则把这些已有程序歌单推送给新档案；未整理则直接跳过。主账户以后完成整理时，所有仍连接该曲库的档案都会接收结果。新增档案的准备不触发其他档案的推荐重算，因此设置页删除“批量每日推荐”及其结果列表。

首次准备的各项工作相互隔离：某张个人歌单数据不足或写入失败，不阻断其他歌单或同库副本。平时不连续弹通知；设置页只在这个档案确需处理时显示一条简短状态，并可展开查看原因或重试这个档案，不提供批量重跑入口。

## 主账户曲库整理与同库同步

- 每个服务器＋曲库有一个明确的主账户整理源。只有它生成、调整、删除分类结果和运行耗时整理；子账户不运行整理。
- 主账户成功发布分类歌单后，向同库所有启用的档案同步本程序创建的副本。主账户更新内容或标题时，更新原有副本，不另建同名歌单。推送到某档案的曲目必须在该档案的 Plex 权限范围内；无可访问歌曲时不发布空副本。
- 主账户删除某张本程序创建的分类歌单后，对所有同库档案传播删除。删除来源的意图和每个目标的完成状态在确认前保留，不能因为来源记录先消失就忘记清理目标。
- 后续同名重建是新的来源版本。先清理旧版本仍存在的本程序副本，再创建新版本；若某目标删除未确认，则该目标的新发布暂缓，避免重复歌单。其他目标可以继续完成，不受一个目标失败拖累。
- 来源与副本按内部来源 ID、版本、目标档案和 Plex 歌单 ID 关联，并验证程序所有权标记。Plex 中同名但非本程序所有的歌单既不接管也不覆盖；冲突只在对应档案显示待处理，不改变其他档案。
- 来源仍存在而用户手动删除了由程序推送的副本时，该副本视为缺失；下次同步可按来源重新创建。子账户没有对分类歌单的独立退出开关，只有移除档案才停止接收。重新创建前仍须确认原 Plex ID 已不存在，避免列表延迟导致重复。
- 同库同步不受播放学习、每日推荐或智能歌单开关影响。某档案被移除后不再接收推送；另一个曲库的档案始终不受影响。

## 移除与重新添加

“移除用户”指移除一个可移除的“用户＋曲库”档案，而非删除整个 Plex 账户或该账户的其他曲库。主账户基础连接单独管理，不因移除其他档案断开。移除需明确确认“删除本程序为此档案创建的 Plex 歌单”，不使用当前“只停止推荐、歌单保留”的含糊措辞。

移除分两阶段：先冻结此档案的新建、更新、同库推送和学习任务；再列举该档案所有可验证为本程序创建的歌单，包括每日推荐、三张内置智能歌单、曲库分类副本、程序创建的最爱及导入结果等。每项按已记录的 Plex ID、档案/曲库身份和所有权证据核实后删除，回读确认不存在；已在 Plex 中不存在的项目视为清理完成。程序只在全部远端清理确认后删除该档案的本地数据和注册项。

不能单凭名称、歌曲内容或一个旧 ID 猜测所有权。若所有权不明、Plex 权限不足、网络失败或删除结果不确定，停止该档案的完成步骤，保留最少的清理记录并显示“移除未完成，可重试”；不宣称已移除，也不允许把同一业务身份作为全新档案重复添加。其他档案、Plex 自建歌单和音乐文件不受影响。清理成功后重新添加才是全新档案，三个开关恢复新档案默认值，不带回旧托管记录。

对旧版本保存的歌单记录，升级时先核对实际 Plex 身份和程序所有权。无法确认的旧记录不自动接管或删除，进入明确的人工核对状态。数据库迁移和清理前备份，能在未写 Plex 时回滚；远端已确认删除的项目不能谎称可通过数据库回滚恢复。

## 自动计划与唯一开关来源

每日推荐和智能歌单的**启用状态只按档案保存一份**。设置页用户表直接读写它；业务页面如展示该状态，必须读同一份值，不设置第二个独立开关。执行时间、周期仍可由主账户在自动任务区域设置，但这里只配置时间，不再有“全部账户启用”的每日/智能开关。调度只遍历对应开关开启且身份有效的档案，首次未发布但数据已足够的档案也能建歌单，不仅更新已发布项目。

曲库整理计划只对各曲库主账户运行；它不会在子账户执行，也不在子账户行出现开关。三种任务继续串行写 Plex；一个档案失败不影响其他档案，重试有退避且不制造重复写入。

升级时保留现有档案、歌单和授权，不把“新增档案默认开启”套到旧档案上。旧档案的每日/智能开关按升级前**实际有效的执行状态**迁移，而不是盲抄可能已失效的旧字段；旧的全局启用值仅用于一次性迁移，此后不再额外拦截档案开关。旧分类自动计划迁移到对应曲库主账户。迁移应可重复运行且结果不变，并用数据库副本验收每个档案升级前后的实际开关、托管 ID 与任务范围。

## 设置页视觉与交互

设置页是一个清晰的管理页面，而不是配置字段堆叠页。页面只保留一次“设置”标题，按以下四组组织：`Plex 连接`、`用户管理`、`自动计划与推荐规则`、`Plex 播放事件`；密码等低频工具收进简洁的折叠区。首次连接 Plex 时，在引导步骤中选择主账户及其第一个曲库；连接完成后，连接区只展示服务器/连接状态与重连或断开，不再把活动档案选择器和音乐库选择器重复摆在这里。以后给同一主账户增加其他曲库，也走用户管理区的“用户 → 曲库 → 添加”流程。用户管理区顶部放这条简洁添加流程，下面才是用户表。

桌面表格布局示意：

```text
用户 · 曲库                 播放学习    每日推荐    智能歌单    操作
shudaizi · 音乐             [开关]      [开关]      [开关]      —
shudai6 · 音乐              [开关]      [开关]      [开关]      移除
shudaizi · 经典音乐         [开关]      [开关]      [开关]      移除
```

列标题只出现一次，开关在固定列对齐；没有移除权限的位置保留对齐空间，但不显示无用的“打开/当前”按钮。窄屏改为单用户卡片，三个开关各有清楚标签，避免横向滚动或挤成一团。用户名为主文字、曲库为次文字，不在标题、下拉和说明中重复整句。正文以 16px 左右为基准，辅助文字不小于 14px，控件点击区域至少 44px 高；保持舒适行高和明确的键盘焦点，不以缩小字体换取布局。主动作颜色统一，危险操作只用于移除/断开，状态只在有意义时出现。

自动计划区只显示时间和周期，避免与用户行里的开关打架；主账户曲库整理的时间设置标明“仅主账户”，不让人误以为对子账户有独立开关。推荐规则集中放一处，不重复说明。Webhook 区保留`复制地址`和`打开 Webhook`两个有用入口；地址过长时截断显示但复制完整地址。正常添加、同步和保存不连发提示；失败状态直接贴近相关用户/设置项，详情可展开。设置页其他控件的对齐、留白、按钮层级及重复文案一并统一。

## 验收与验证

1. 同一 Plex 用户添加两库产生两个独立档案；移除其中一个不影响另一个的歌单、开关和学习数据。
2. 新档案只生成自己的四张个人歌单，足够数据才发布；已有档案不重算；同库已整理分类只复制既有结果，未整理不触发扫描。
3. 主账户新增、修改、删除、同名重建分类歌单，在同库目标创建、更新、删除且不重复；跨库目标无变化，失败目标可单独重试。
4. 每日、智能、播放学习三个开关作用域独立；智能开关覆盖每周常听、时光胶囊、最近新增；关闭更新保留已发布歌单。所有页面显示同一状态。
5. 移除删除此档案全部经核实的程序歌单和本地状态；Plex 自建歌单及音乐文件保持不变。断网、权限不足、同名原生歌单、所有权不明和远端回读不一致时不误删、不假成功、不允许带旧数据重新添加。
6. 设置页没有批量每日推荐、重复活动档案选择器或全局每日/智能启用开关；三个开关整齐对齐、窄屏可用、文字可读，Webhook 两按钮保留。
7. 使用临时 Plex 替身与隔离数据库覆盖上述流程，再在现有数据库副本上检查旧档案和托管 ID 的迁移；视觉验收覆盖桌面、窄屏、键盘操作和主要错误状态。真实服务发布前另行检查备份、回滚与任务状态。

本设计经用户确认并形成实施计划之前，不修改产品代码或部署。
