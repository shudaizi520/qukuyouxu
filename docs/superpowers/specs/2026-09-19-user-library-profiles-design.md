# Plex 用户与音乐库独立档案设计

## 背景

当前程序把一个 Plex 用户固定对应为一个推荐档案，并把新增家庭成员直接绑定到管理员当时选择的音乐库。这个模型无法覆盖“同一服务器上为自己和长辈准备不同音乐库”的正常家庭场景，也造成了几类连锁问题：

- 同一个 Plex 用户能访问多个音乐库，却只能保存一个库。
- 共享用户实际可以访问多个音乐库，但界面没有音乐库选择入口。
- 已有托管歌单时，切换音乐库只会被拦截，用户无法为同一账户增加第二个库。
- 今日推荐页面依赖全局当前档案和 45 秒轮询，切换用户后会先显示旧用户内容，再突然变为空白。
- 页面只展示临时 `daily_plan`。即使 Plex 中的已发布歌单、`daily_managed` 和发布历史仍在，临时预览被作废后也会错误显示“待生成”。

## 目标

把推荐档案的业务身份改为“Plex 用户 + Plex 服务器 + 音乐库”。同一 Plex 用户可以拥有多个互不干扰的音乐库档案，每个档案独立维护推荐、分类、播放学习、缓存、历史和托管歌单。

同时修正跨用户页面状态：用户切换后页面立即加载目标档案；临时预览消失时，仍能正确显示该档案已经发布的今日歌单。

## 非目标

- 不合并不同音乐库的歌曲、历史或缓存。
- 不把旧用户缓存自动导入新档案。
- 不删除或改名现有 Plex 歌单。
- 不重建整个程序，不改变现有 Plex、QQ 音乐授权方式。
- 本轮先在本地实现和验收，不在验证完成前发布 GitHub 或更新 NAS。

## 业务模型

### 名词

- **Plex 用户**：管理员、Plex Home 成员或共享用户，对应独立 Plex 身份和访问令牌。
- **音乐库**：某台 Plex 服务器上的一个 `artist` 类型资料库。
- **推荐档案**：一个 Plex 用户在一台服务器的一个音乐库上的独立工作空间。

推荐档案的唯一业务身份为：

```text
(用户类型, Plex 用户 ID, Plex 服务器 machine identifier, 音乐库 ID)
```

不同音乐库即使属于同一用户，也必须是不同档案。相同业务身份重复添加时返回现有档案，不重复创建。

### 档案标识与兼容

- 现有 `default` 和 `shared-*` 档案 ID 保持不变，现有数据原地保留。
- 新增的同用户第二音乐库使用新的稳定内部 ID；ID 由规范化身份摘要生成，不使用可变的用户名或库名。
- 注册表继续保存账户、服务器、音乐库和令牌，但增加可计算的业务身份键，用于去重和校验。
- 不重命名旧档案，不移动旧缓存，不通过复制数据库键完成升级。

## 音乐库发现

- 后端使用目标档案自己的 Plex 令牌读取其可访问的服务器和音乐库。
- 音乐库列表不再依赖只在官方登录期间产生的临时 `plex_connection.sections`。
- 仅返回 `artist` 类型音乐库；每一项包含稳定库 ID、显示名称和服务器身份。
- 当前连接暂时不可达时，保留已经保存的音乐库作为当前项，但不伪造其他可选项。
- 前端不得使用管理员的音乐库列表替代家庭成员或共享用户自己的可访问列表。

## 用户流程

### 当前档案

“账户与成员”顶部始终明确显示当前组合，例如：

```text
shudaizi · 音乐
shudaizi · 经典音乐
shudai6 · 经典音乐
```

当前用户可访问的音乐库加载完成后始终可以选择，不因档案来源是管理员、Home 成员或共享用户而隐藏。

### 添加家庭成员或共享用户

添加流程保持简洁，但必须按顺序完成两项选择：

1. 选择 Plex 用户。
2. 选择该用户实际可访问的音乐库。

确认后创建对应的推荐档案并切换过去。不得继续把管理员当前库 ID 硬编码给新用户。

### 同一用户增加另一个音乐库

- 当前档案没有托管歌单时，允许原地切换音乐库；切换在一个事务内更新注册表和档案设置，并清空只属于旧库的派生数据。
- 当前档案已有任何托管歌单、已移除托管记录或未完成写入时，不修改原档案身份。选择另一个库时，为同一 Plex 用户创建新的音乐库档案并打开它。
- 新档案只复用经验证的账户、服务器和令牌。它不复制目录缓存、分类结果、反馈、播放行为、推荐历史、预览、快照或托管歌单。
- 可以复制纯偏好参数，例如推荐数量、更新时间和比例设置；所有会引用具体歌曲或歌单 ID 的状态必须为空。
- 原档案和原 Plex 歌单保持不变，用户随时可以切换回来。

### 切换失败

- 后端是唯一事实来源。只有后端成功后，前端才提交新的选中项。
- 请求失败时，选择框立即恢复到已保存的音乐库，不得继续显示未生效的值。
- 重复点击同一目标必须幂等，不得创建多个相同档案。

## 今日推荐状态

### 档案作用域

- 今日推荐页面每次请求都明确绑定一个档案 ID，不再只依赖安装级全局“当前档案”。
- 档案切换成功后立即刷新今日推荐、智能歌单、曲库整理和设置页面状态，不等待 45 秒轮询。
- 后台轮询只能刷新当前页面绑定的档案，不能因另一标签页切换用户而静默换成另一个人的内容。
- 页面顶部显示当前“用户 · 音乐库”，避免用户不知道正在操作谁的歌单。

### 临时预览与已发布歌单

`daily_plan` 只代表待发布或刚发布的工作计划，不能继续兼任“最后一次已发布歌单”的页面数据源。

- 发布成功时保存一份只读的 `daily_published_view`，包含档案身份、计划 ID、Plex 歌单 ID、发布时间和用于展示的歌曲摘要。
- 修改推荐参数、反馈、学习账户或音乐库时，只能作废待发布预览，不得删除最后一次已发布视图。
- 如果存在待发布预览，页面展示预览和“发布”操作。
- 如果没有预览但存在 `daily_published_view`，页面展示“已发布”及最后一次歌单内容，并提供“生成新一批”。
- 对旧数据升级时，优先从最近一次已发布 `daily_plan` 构建视图；若该计划已经不存在，则用 `daily_managed` 和 `daily_history` 显示“已发布”摘要，不虚构歌曲标题。下一次成功发布后补齐完整视图。
- `daily_managed` 仍是写入安全依据，`daily_published_view` 只负责稳定展示，不能绕过指纹、作用域或回读校验。

## 状态隔离

以下数据全部按推荐档案隔离：

- Plex 与 QQ 曲目缓存、目录和元数据校对
- 分类选择、预览、托管歌单和快照
- 今日推荐预览、已发布视图、发布历史和自动更新
- 智能歌单、反馈、播放事件、儿童隔离和学习结果
- 后台任务进度、错误和最后运行时间

跨档案仅共享安装级登录账户、全局安装标识和安全会话。任何后台任务都必须在开始时固定档案 ID，并在整个任务期间使用同一作用域。

## 接口设计

新增或调整以下接口，具体路径在实施计划中按现有路由风格落地：

- 读取某档案自己的可访问音乐库。
- 为现有 Plex 用户增加一个音乐库档案。
- 在无托管状态时原地切换音乐库。
- 选择活动档案时返回档案完整显示信息，并让前端立即重新加载。
- `/api/status` 及各业务状态接口接受显式档案 ID，并校验该档案已启用。

所有写接口必须在同一个共享操作锁内完成身份复核、重复检测、状态初始化和注册表更新。不能先更新选择框或注册表，再异步补写档案状态。

## 迁移与恢复

- 升级不需要破坏性数据库迁移。
- 启动时为旧档案计算缺失的业务身份键，但不修改档案 ID。
- 已有 `default` 继续使用当前音乐库及全部历史数据。
- 已有共享档案继续使用当前音乐库；用户需要第二个库时新增档案，不覆盖旧档案。
- 迁移前后分别检查每个旧档案的设置、托管歌单、缓存、历史和快照数量。
- 若新版本启动失败，可直接回到旧镜像和原数据库；新建档案不会触碰旧档案的数据键。

## 安全边界

- 目标音乐库必须由目标用户令牌实时列出，并属于已保存的 Plex 服务器。
- 有托管状态的档案禁止原地改变账户、服务器或音乐库身份。
- 新档案建立失败时不留下半成品注册项。
- 已有同业务身份档案被停用时，恢复原档案而不是创建重复档案。
- 用户切换、建档、移除、恢复、生成和发布共用串行操作门，避免请求交叉污染档案。
- 任何失败都不得删除 Plex 歌单、清空旧档案缓存或改变自动任务开关。

## 界面原则

- 保持现有简洁卡片布局，不增加大段说明文字。
- 主要按钮使用直接动作名称：`添加用户`、`添加音乐库`、`打开`、`生成新一批`、`发布到 Plexamp`。
- 必要错误用一句话说明并给出唯一下一步；技术细节放运行状态，不堆在主界面。
- 用户和音乐库选择放在同一模块，不能让用户到另一个设置页寻找缺失步骤。
- 当前档案、当前音乐库和当前操作对象在所有业务页面保持一致。

## 验收标准

1. 管理员和 `shudai6` 都能分别列出其实际可访问的 `音乐 · 11` 与 `经典音乐 · 15`。
2. 添加共享用户时可以选择库 11 或库 15，不再强制使用管理员当前库。
3. 同一 Plex 用户可以同时拥有两个音乐库档案，名称清楚、数据互不混用。
4. 无托管档案可以安全原地换库；有托管档案换库会新建档案，旧歌单和旧状态保持不变。
5. 后端拒绝操作时，前端选择框恢复为原值。
6. 切换用户后所有页面立即显示目标档案，不出现约 45 秒后内容突然消失的现象。
7. 在其他标签页切换档案，不会让当前页面静默换到另一个用户。
8. `daily_plan` 被设置变更作废后，已发布的今日歌单仍显示为“已发布”，Plex 歌单及发布历史保持不变。
9. 旧 `default` 和 `shared-*` 档案升级后数据数量、托管 ID 和授权身份不变。
10. 新用户从零安装可以完成连接 Plex、选择用户与音乐库、生成预览、发布以及再次更新的完整流程。

## 测试范围

- 注册表单元测试：业务身份去重、旧 ID 兼容、停用档案恢复、创建失败回滚。
- 音乐库发现测试：管理员、Home 成员、共享用户、多库、离线和无音乐库。
- 切换测试：无托管原地切换、有托管新建档案、失败回滚、并发请求串行化。
- 隔离测试：目录、缓存、学习、反馈、每日推荐、分类和智能歌单不跨档案泄漏。
- 今日推荐回归测试：跨标签切换、立即刷新、预览作废后保留已发布视图、旧数据降级展示。
- HTTP/UI 测试：新用户完整流程、共享用户选库、同用户多库、按钮与状态一致。
- 全量测试、静态检查、编译检查、仓库隐私检查和全新数据目录冒烟测试全部通过后，才允许发布。

## 发布顺序

1. 在本地创建回归测试并实现。
2. 使用全新临时数据目录完成新用户端到端验收。
3. 使用现有数据库副本完成兼容与数据不变性验收。
4. 用户确认界面和实际操作正常。
5. 最后再更新版本、GitHub、镜像和 NAS；任一步验证失败都停止发布。
