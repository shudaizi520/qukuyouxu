# 程序托管歌单统一收敛设计

## 状态

- 日期：2026-09-28
- 状态：待用户复核
- 范围：每日推荐、内置智能歌单、曲库整理生成的托管歌单
- 发布边界：本设计只授权编写实现计划；不授权发布 GitHub 版本或更新 9512

## 背景

当前三类程序托管歌单没有遵守同一套维护规则：

- 每日推荐已经按程序计算结果替换成员，但仍可能被旧的未决快照阻塞。
- 内置智能歌单已经能够覆盖成员变化和恢复标题，但被删除后不会自动重建，旧版留下的 `uncertain` 快照也可能永久暂停自动更新。
- 曲库整理仍混有追加式维护、人工改动保护和分类专属阻塞；同一个“自动更新已开启”在不同歌单上表现不同。

用户已经明确：这些歌单由程序生成。对应自动更新开关开启时，Plex 中的人工修改只影响当时；下一次计划任务必须恢复程序计算出的状态。只有关闭对应开关后，程序才停止维护。

## 目标

1. 三类歌单使用同一个“程序托管歌单收敛”规则，不再各自判断人工改动。
2. 自动更新开启时，恢复程序确定的名称、所有权说明和精确成员集合；人工增歌、删歌、改名或删除整张歌单都不会形成永久待核对状态。
3. 歌单被删除时，在确认 Plex 明确返回“不存在”后自动重建，并更新本地托管 ID。
4. 自动更新关闭时不执行任何自动恢复、重命名、重建或成员覆盖。
5. 网络故障只进入有限重试；真正的账户、资料库或归属冲突才停止写入。
6. 自动收敛旧版本遗留的可判定未决状态，清除当前“每周常听”的错误暂停。
7. 保持实现集中、可测试，不在每日推荐、智能歌单和曲库整理中复制三套分支。

## 非目标

- 不修改每日推荐、智能歌单或曲库整理的选歌算法。
- 不改变三个全局任务的执行周期、小时和串行顺序。
- 不接管只有同名、但没有任何本应用托管证据的用户歌单。
- 不删除音乐文件，不修改 Plex 曲目标签。
- 不要求 Plex 严格保存歌曲顺序。Plex 对普通音频歌单的 MOVE 支持并不稳定；成员集合、标题和归属说明是强制状态，顺序仅尽力保持。
- 不把临时网络故障伪装成成功，也不在无法确认创建结果时盲目重复创建。

## 开关语义

设置页三项全局自动任务开关分别控制对应歌单族：

- `每日推荐` 控制每个满足前置条件档案的每日推荐歌单。
- `智能歌单` 控制每周常听、时光胶囊和最近新增。
- `新增歌曲整理` 控制曲库整理生成的基础分类和主题分类歌单。

开关开启表示程序拥有该歌单族的最终状态：到期时必须收敛。开关关闭表示不进行任何自动维护，Plex 中现状完整保留。曲库整理中用户明确点击某一分类的“停止维护”仍优先于全局开关；只跳过该分类，不影响同族其他分类。

手动“预览并发布”继续可用。它使用与自动任务相同的收敛器，但仍要求用户确认本次程序计算结果。预览之后发生的歌单成员、名称或说明变化不会阻止发布；曲库曲目本身、账户、服务器或资料库发生变化仍会使预览失效。

## 统一托管状态

程序计算出的目标状态包含：

- 当前档案、Plex 服务器和音乐资料库范围。
- 稳定的分类键，例如 `daily`、`smart:weekly` 或 `base:国语`。
- 程序目标标题。
- 当前安装实例与分类键生成的所有权标记。
- 非空、去重、属于当前资料库的目标曲目 ID 集合。

本地托管记录保存当前 Plex 歌单 ID、范围、服务器身份、目标标题、最近成功成员指纹和最近成功快照。成员指纹只用于诊断和确认写入结果，不再作为“用户改过所以拒绝更新”的条件。

## 公共收敛器

新增一个聚焦的后端模块，负责所有普通程序托管歌单的读取、恢复与收敛。每日推荐、智能歌单和曲库整理只负责提供目标状态，不再自行实现成员差异和删除恢复策略。

公共收敛器执行以下流程：

1. 验证当前档案、服务器和资料库仍与托管记录一致。
2. 按托管 ID 读取 Plex 歌单。
3. 如果歌单存在：
   - 将标题恢复为程序目标标题。
   - 将说明中的所有权标记恢复为当前正确标记，同时保留程序说明文本。
   - 从最新真实成员出发，删除不在目标集合中的成员，再补齐缺少成员。
   - 回读确认标题、标记和成员集合与目标一致。
4. 如果 Plex 明确返回该 ID 不存在：
   - 先按当前所有权标记查找是否存在上次创建成功但本地未收到 ID 的唯一歌单。
   - 找到唯一匹配时采用该歌单并继续收敛。
   - 找不到时创建一张新歌单，回读确认后替换本地托管 ID。
5. 如果读取失败是超时、连接失败、429 或 5xx，不判断为删除，不创建歌单，交由现有有限重试调度处理。
6. 如果存在多个相同所有权标记的候选，或者同名歌单存在但没有本应用归属证据，停止该歌单写入并报告真实冲突，不自动覆盖。

为支持第 4 步，Plex 客户端需要把“明确不存在”与普通读取失败区分为不同异常；业务层不得依赖中文错误字符串判断。

## 写入并发与幂等性

人工修改不是冲突。公共收敛器在每次写入前读取最新状态，并以最新状态为起点计算差异。

如果成员在读取后、第一次写入前再次变化，收敛器重新读取并重新计算一次，而不是留下永久待核对状态。如果写入已经发出但响应不确定，不盲目重复同一条创建请求；后续重试先通过托管 ID 和所有权标记发现实际状态，再继续收敛。

每次成功都必须回读。只有回读确认目标标题、所有权标记和成员集合一致，才更新本地托管记录和成功快照。重复运行相同目标必须得到 `unchanged`，不能重复创建或追加重复歌曲。

## 三类歌单接入

### 每日推荐

每日算法仍生成当天目标成员。自动任务到期后直接调用公共收敛器：人工成员变化、改名、说明变化和歌单删除均由本次任务恢复。原有“固定歌单 ID”在歌单仍存在时保持；只有明确删除后重建才产生新 ID。

### 内置智能歌单

每周常听、时光胶囊和最近新增继续独立计算、独立成功或失败。每种歌单把计算结果交给公共收敛器。某一种发生真实冲突时不阻断其他两种。

### 曲库整理

基础分类和主题分类从追加式维护改为目标集合收敛：不属于当前程序计算结果的人工新增成员会被移除，人工删除的应有成员会被补回，标题与说明会恢复。语言、年代和主题分类不再因为 Plex 当前成员与程序结果不同而要求人工核对；分类算法现有证据门槛仍然保留，目标数据为空或不可靠时不得清空现有歌单。

## 删除与重建

“整张歌单被删除”是开启自动更新后的正常漂移，不是后台异常：

- 明确 Not Found：自动重建。
- 网络错误或无权限：重试，不重建。
- 同名无归属歌单：不接管、不删除；显示归属冲突。
- 重建成功：原托管记录原子替换为新 ID，旧成功历史保留为历史记录。
- 重建结果未确认：下一次先查所有权标记，避免重复创建。

## 旧状态收敛

升级后不直接批量删除历史快照。下一次对应自动任务运行时：

1. 对 `prepared`、`uncertain` 或 `restoring` 的程序托管歌单，读取 Plex 当前真实状态。
2. 使用当天新计算目标运行公共收敛器。
3. 成功后把旧未决快照标记为 `superseded`，记录被哪次成功收敛取代。
4. 清除对应的 `auto_paused_reasons`、`auto_retry_state` 和旧版暂停兼容字段。

当前“每周常听”记录属于写入前检测到变化、尚未执行写入的旧版快照。实现上线后的第一次智能歌单更新会按上述流程自动取代它，不需要用户逐首核对或手工修改数据库。

## 状态与错误呈现

以下情况属于正常维护，不显示“待核对”：

- 成员被人工增加、删除或重新排序。
- 标题或说明被人工修改。
- 托管歌单被明确删除后自动重建。
- 旧未决快照被一次新的成功收敛取代。

以下情况显示“等待重试”：

- Plex 超时、拒绝连接、429 或 5xx。
- 写后回读暂时仍返回旧状态。

以下情况才显示需要处理：

- 当前账户、服务器或资料库与托管记录不一致。
- 出现多个相同所有权标记的候选歌单。
- 同名目标已被一个无法证明归属的歌单占用。
- 程序无法生成安全的非空目标成员集合。

错误信息必须说明具体歌单和原因，不再用泛化的“后台异常”或“待核对”代替真实状态。

## 数据一致性

- 单个歌单的远端收敛成功后，一次性更新托管记录、计划结果、快照和暂停状态。
- 不对三个歌单族做跨 Plex 请求的数据库大事务；远端调用不能持有 SQLite 写事务。
- 同一个全局任务锁继续保证本应用不会并发写同一 Plex。
- 每个歌单独立落盘，单个失败不撤销其他已经回读确认的成功结果。
- 新字段向后兼容；旧版本读取额外字段时不受影响。

## 测试策略

实现严格采用测试先行。

### 公共收敛器

- 人工增加歌曲后恢复精确目标集合。
- 人工删除歌曲后补回目标成员。
- 人工改名、修改说明后恢复目标元数据。
- 明确删除后重建且更新托管 ID。
- 网络读取失败不被当成删除，不创建重复歌单。
- 创建响应不确定后能通过所有权标记发现唯一结果。
- 同名无归属歌单和多个归属候选均拒绝接管。
- 相同目标重复运行返回 `unchanged`，无重复成员和重复歌单。
- 写入前并发变化会重新读取并最终收敛。

### 三类集成

- 每日推荐、三种智能歌单、基础分类和主题分类都覆盖成员增删与改名。
- 每一类歌单被删除后在下一次启用的计划任务中重建。
- 对应全局开关关闭时，人工修改和删除均保持不变。
- 曲库整理单项“停止维护”只排除该分类。
- 一个智能歌单真实失败不会阻断另外两个。
- 旧 `uncertain` 快照在新任务成功后变为 `superseded` 并清除暂停。
- 目标为空或证据不足时保留当前歌单，不执行清空。

## 实施边界与文件职责

- 新公共模块：只负责普通托管歌单的目标状态收敛和结果模型。
- Plex 客户端：只增加结构化 Not Found 与按所有权标记发现歌单所需能力。
- 每日推荐、智能歌单、曲库整理：保留目标计算和各自业务记录，删除重复的漂移阻塞逻辑，调用公共收敛器。
- 调度器：保留现有串行与有限退避，只调整正常漂移、临时错误和真实冲突的分类。
- 状态页：消费统一结果，不新增复杂操作面板。

不借本次修改重写推荐算法、前端页面、认证、播放器或部署结构。

## 成功标准

- 任一对应自动开关开启时，程序托管歌单在下一次计划任务后恢复程序标题、归属标记和精确成员集合。
- 删除整张托管歌单后能够自动重建，且网络故障不会触发误重建。
- 开关关闭或分类明确停止维护时，程序不再修改相应歌单。
- 人工改动不再产生永久待核对或后台异常。
- 当前“每周常听”旧暂停能由下一次成功更新自动消除。
- 三类歌单共享一个收敛模块，业务模块中不再复制成员同步、缺失重建和漂移判断。
