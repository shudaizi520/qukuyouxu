# 外部歌单导入、Plex 建单与缺失歌曲补齐设计

日期：2026-09-20
状态：待用户审阅

## 1. 目标

增加一套独立的“外部歌单”功能，让用户能够导入 QQ 音乐、网易云音乐或本地歌单文件，并在当前 Plex 用户与音乐资料库中生成对应歌单。

完整闭环为：

```text
导入外部歌单
    ↓
与当前 Plex 曲库匹配
    ↓
可靠匹配的歌曲按原顺序创建 Plex 歌单
    ↓
不确定匹配交给用户确认，缺失歌曲保留为补歌清单
    ↓
用户通过官方音乐客户端补齐歌曲
    ↓
Plex 扫描后自动重新匹配并补入原歌单
```

设计必须适合不了解匹配算法和接口的普通用户：主页面只展示来源、数量、结果和必要操作，不展示内部评分、缓存键或接口术语。

## 2. 产品边界

### 本期包含

- 导入公开的 QQ 音乐歌单或排行榜链接。
- 导入公开的网易云音乐歌单或排行榜链接。
- 导入 M3U、M3U8、TXT 和 CSV 文件。
- 与当前配置档案对应的 Plex 音乐资料库比较。
- 将可靠匹配结果按来源顺序创建为助手托管的 Plex 歌单。
- 保存待确认和缺失歌曲，后续重复匹配。
- 为缺失歌曲生成适合带到官方音乐客户端的补歌清单。
- 在网页中试听已经匹配到 Plex 的歌曲。
- 手动刷新来源；可选跟随外部来源更新。

### 本期不包含

- 不登录用户的 QQ 音乐或网易云音乐账号。
- 不保存平台 Cookie、二维码登录票据或第三方账号密码。
- 不调用未经公开承诺的私有写入接口，在平台账号内直接创建歌单。
- 不从 QQ 音乐、网易云音乐或其他流媒体下载音频。
- 不保证普通 NAS 网页链接能被音乐平台当作歌单导入。
- 不修改、覆盖或删除用户手工创建的 Plex 歌单。

如果未来存在面向个人应用、稳定且合规的官方歌单写入接口，可在平台适配层增加可选写入能力，不改变本设计的导入、匹配和 Plex 建单模型。

## 3. 用户界面

### 3.1 导航与空白页

顶栏增加`外部歌单`。首次进入只显示一个主要输入区域：

```text
外部歌单

粘贴 QQ音乐或网易云音乐歌单链接
[____________________________________] [开始分析]

[上传歌单文件]
支持 M3U、M3U8、TXT、CSV
```

页面不预先展示空表格和大量说明。无法识别的链接或文件在输入区域就近显示明确原因。

### 3.2 分析结果

成功读取来源后展示：

```text
百万收藏                                      QQ音乐
共 50 首

已匹配 31        待确认 3        曲库缺失 16

[在 Plex 创建“百万收藏”歌单（31首）]

[已匹配] [待确认] [曲库缺失]
```

主按钮永远表达真实动作和实际歌曲数，不使用`发送到 QQ 音乐`等容易误解的名称。创建前可以查看所有将写入 Plex 的歌曲。

### 3.3 已托管歌单

创建后同一页面变为管理卡片：

```text
百万收藏                                      QQ音乐
已进入 Plex 31 / 50 首

[打开 Plex 歌单] [重新匹配] [刷新来源] [生成补歌清单]
```

操作菜单提供`停止跟随来源更新`和`删除助手歌单`。删除只删除明确记录为本功能托管的 Plex 歌单与本地导入记录，必须二次确认；任何手工歌单均不受影响。

### 3.4 待确认歌曲

每行并排展示来源歌曲和最多三个 Plex 候选，默认不勾选。用户可以：

- 确认正确候选；
- 标记为曲库缺失；
- 忽略该来源歌曲。

确认结果保存到当前外部歌单，不污染其他用户、资料库或无关歌单。若 Plex 对应歌曲以后被移除，确认自动失效并回到缺失状态。

### 3.5 补歌清单

`生成补歌清单`只处理当前导入歌单仍然缺失的歌曲：

```text
补齐缺失歌曲

已整理 16 首，已去重并规范名称。

[复制歌单内容] [下载歌单长图] [更多格式]

1. 复制清单或下载长图
2. 打开 QQ音乐或网易云音乐的外部歌单导入
3. 粘贴文字或上传图片并确认创建
4. 在官方客户端中自行下载
```

`更多格式`提供 TXT 和 CSV。M3U 是包含可播放地址的格式，缺失歌曲没有本地地址，因此不把“缺失歌曲 M3U”伪装成可播放文件。

可提供`复制清单页面链接`，用途仅为在同一局域网的手机或电脑上打开、查看和复制。界面必须注明：

> 此链接用于查看清单，不会直接在音乐平台创建歌单。

每首缺失歌曲另有`去 QQ 音乐搜索`和`去网易云音乐搜索`。搜索失败不会改变歌曲状态。

## 4. 外部来源适配

外部来源通过小型统一接口接入，业务层不直接理解各平台返回结构：

```text
识别输入 → 来源适配器 → 标准歌单快照 → 匹配器
```

标准快照至少包含：来源类型、来源稳定 ID、标题、抓取时间，以及每首歌曲的来源 ID、位置、歌名、完整歌手列表、专辑、时长、版本标记和原始页面地址。

首期适配器：

- `QQPublicPlaylistSource`：公开歌单和排行榜。
- `NetEasePublicPlaylistSource`：公开歌单和排行榜。
- `M3UPlaylistSource`：M3U/M3U8 文件。
- `TextPlaylistSource`：TXT/CSV 的歌名与歌手清单。

同一来源重复导入时返回已有记录并刷新，不建立重复任务。每次成功抓取形成新的“最后有效快照”；超时、限流、临时不可用或返回空列表时保留旧快照，不把托管歌单清空。

### 网络安全

- 只允许受支持平台的 HTTPS 域名；每次重定向都重新校验。
- 拒绝回环、局域网、链路本地和其他保留地址，防止服务端请求伪造。
- 限制响应体、歌曲数量、重定向次数和连接/读取时间。
- 输入链接中的凭据、片段和无关追踪参数不保存、不写日志。
- 文件导入限制大小和最多 10,000 首；非法编码或畸形条目按行报告，不执行任意路径或 URL。

## 5. 匹配规则

匹配分为`可靠匹配`、`待确认`、`曲库缺失`三种公开状态。内部可以计算分值，但界面只显示结果和简短原因。

### 5.1 标准化

- 统一全角/半角、大小写、空白和常见标点。
- 分离歌名主体与现场版、伴奏、混音、翻唱、重制、纯音乐、DJ 等版本标记。
- 歌手按集合比较，不把第一位歌手相同视为完整相同。
- 保留中文、繁体、英文及常见艺名别名，不能通过删除全部括号内容来提高假匹配率。

### 5.2 自动匹配门槛

只有存在唯一、可靠候选时才自动匹配：

- 歌名主体高度一致；
- 主要歌手一致；
- 版本标记不冲突；
- 时长存在时处于允许误差内；
- Plex 媒体真实可访问。

专辑和年份用于提高或降低置信度。多个候选接近、歌手不完整、版本冲突或只有模糊歌名时进入待确认，绝不为了提高匹配数量而随便选一首。

匹配结果绑定来源歌曲和 Plex `ratingKey`，并记录所依据的曲库修订号。重新扫描后只有受影响或仍缺失的记录需要重新计算，不必每次全量重跑。

## 6. Plex 歌单生命周期

### 初次创建

- 只写入可靠匹配和用户已经确认的歌曲。
- 按外部来源的原始顺序排列。
- 同一 Plex 歌曲在一个来源歌单中最多出现一次。
- 歌单名称冲突时不接管现有手工歌单；提示用户使用建议名称或明确选择另一个名称。
- 创建完成后保存 Plex 歌单 ID、配置档案、来源 ID、已发布快照和管理签名。

### 缺失歌曲后来补齐

“新增歌曲整理”完成 Plex 曲库刷新后，自动重新匹配该配置档案所有待确认和缺失记录。新成为可靠匹配的歌曲加入原托管歌单，并按来源位置重新排列；已经存在的项目不重复添加。

例如首次只匹配 31/50 首，后来下载 5 首并被 Plex 扫描，状态更新为 36/50，五首自动出现在原“百万收藏”歌单的正确位置。

### 跟随来源更新

用户可以为已经托管的外部歌单开启`跟随来源更新`。刷新复用设置页现有的`新增歌曲整理`计划，不增加第四个自动任务，也不在本页面增加重复的时间设置。

- 新增来源歌曲进入匹配流程，可靠匹配后加入 Plex。
- 来源移除歌曲只从本功能托管的对应歌单移除，不删除音乐文件。
- 一次刷新若移除数量超过旧快照的 20% 或 20 首（取更严格者），暂停应用并要求确认，防止平台异常返回破坏歌单。
- 来源失败、结果为空或总数异常时保留最后有效快照。
- 手动`刷新来源`不改变自动任务的下次执行时间。

## 7. 数据模型与隔离

新增规范化 SQLite 表，避免把不断增长的导入记录塞进单个 JSON 状态值：

- `external_sources`：配置档案、平台、外部 ID、URL、标题、同步设置和最后有效修订。
- `external_tracks`：来源歌曲、原始位置和标准化元数据。
- `external_matches`：Plex 歌曲、状态、置信原因、人工确认与曲库修订。
- `external_managed_playlists`：Plex 歌单 ID、发布快照、管理签名和同步状态。
- `external_runs`：最近运行的开始、结束、结果和可公开错误摘要。

所有业务表都以 `profile_id` 为第一隔离边界。任何查询和写入都必须同时验证当前登录会话、当前配置档案与目标资料库；禁止仅凭来源 ID 或 Plex 歌单 ID 跨档案读取。

现有配置档案、曲库缓存、每日推荐、智能歌单、播放学习和 QQ 分类资料不迁移、不重算。数据库升级只增加表和索引，可安全重复执行。

## 8. 网页试听

已匹配歌曲提供小型播放按钮，帮助用户判断是否匹配正确：

- 浏览器只访问曲库有序的受保护音频路由，不接触 Plex Token。
- 后端验证当前会话、配置档案、资料库和 `ratingKey`，然后流式代理 Plex 音频。
- 支持 HTTP Range，不把整首歌一次读入内存。
- 首期不为试听主动转码；浏览器不支持源格式时显示`在 Plex 中打开`。
- 同一会话限制并发流数量，断开后立即关闭上游响应。
- 网页试听不写入 Plex 播放学习，避免人工核对版本污染偏好模型。
- 缺失歌曲没有本地音频，不提供来自第三方平台的代理试听。

## 9. 任务与性能

- 导入、刷新、匹配和 Plex 写入作为有真实进度的后台任务运行，不阻塞网页请求。
- Plex 写入继续服从现有全局串行队列，不能与每日推荐、智能歌单或曲库整理同时修改 Plex。
- 一次运行只读取一份当前资料库快照；批量匹配复用索引，不逐首重新请求完整 Plex 曲库。
- 来源分页、数据库写入和 Plex 更新都分批执行，避免数千首歌造成高内存峰值。
- 外部平台临时失败采用持久化退避，不高频重试。
- 一个配置档案失败不能污染或清空其他配置档案的数据。

## 10. 错误处理

用户可见错误只说明可采取的下一步：

- 私有或失效链接：提示改用公开分享链接或上传文件。
- 平台暂时不可用：保留上次结果，可稍后重试。
- Plex 不可达：保留分析结果，不把创建操作标记为成功。
- 写入中断：重新运行时按来源修订和 Plex 歌单 ID 幂等恢复，不重复建单。
- 歌单被用户在 Plex 删除：标记为已断开，允许重新创建，不偷偷接管同名歌单。
- 来源发生大规模删除：停在确认状态，继续保留当前 Plex 内容。

日志不记录 Plex Token、平台 Cookie、Webhook 密钥、完整查询参数或用户上传的整份歌单内容。

## 11. 验证要求

实现遵循测试驱动开发，至少覆盖：

- QQ、网易云、M3U、TXT、CSV 的正常、分页、空结果和畸形输入。
- URL 域名、重定向、私网地址、响应大小和文件大小限制。
- 中文标点、多歌手、同名歌、现场版、伴奏、翻唱、混音和时长冲突。
- 唯一可靠匹配、多个候选待确认、完全缺失三条路径。
- 创建顺序、去重、幂等重试、歌单名称冲突和人工确认持久化。
- 新歌扫描后自动补齐并恢复来源顺序。
- 来源失败保留旧快照，大规模删除进入确认而不直接应用。
- 多 Plex 用户、多音乐资料库和多导入来源之间的严格隔离。
- 补歌清单只包含当前仍缺失歌曲，输出文字和 CSV 正确转义。
- 音频代理的登录校验、档案校验、Range、断流和并发限制。
- 现有每日推荐、智能歌单、曲库整理、播放学习和自动任务的完整回归测试。

在发布前使用复制的数据目录和独立端口验收，不直接拿生产数据库试迁移。验收通过后再发布为新的次版本；建议版本为 `v1.3.0`。

## 12. 与成熟产品的取舍

借鉴 Playlist Lab 一类成熟工具的做法：平台适配器、统一歌曲模型、缺失歌曲持久化、可重试任务和受保护音频代理。改进之处是：

- 匹配结果不只有“找到/找不到”，增加明确的待确认区，降低错歌率。
- 缺失歌曲不是一次性报告，而是随着 Plex 新增歌曲自动补回原歌单。
- 外部来源异常时保留最后有效快照，并拦截大规模错误删除。
- 每个 Plex 用户与音乐资料库独立，适合家庭多用户、多曲库场景。
- 不把第三方登录凭据和非公开写接口作为核心依赖。

实现必须独立完成，不复制许可证不明确的第三方源代码。
