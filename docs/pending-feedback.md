# 待处理反馈（2026-09-21）

状态：这是 1.4.10 反馈时的原始记录，不再代表当前实现状态。对应修复已纳入 1.4.11 候选版本；具体上线状态以发布标签和实际部署为准。保留以下原始问题描述供回归核对。

## “我的最爱”入口与 Plex 歌单

当前 v1.4.10 行为：网页左侧的“我的最爱”是固定的评分视图，没有 Plex 歌单 ID；它实时读取当前 Plex 用户的四星、五星歌曲。网页爱心写入 Plex 五星，取消爱心写入零星。原有同名 Plex 智能歌单仅从网页侧栏隐藏，Plex 中没有删除。

评分口径已确认：Plexamp 的“单星评价”是有星／无星的操作模式，有星在 Plex 中写成评分值 10；它不是五星制中的 1 星。五星制里只有 4～5 星（评分值 8～10）算喜欢，1～3 星不算。网页爱心、网页“我的最爱”和拟迁移的 Plex 规则歌单应采用同一评分口径；不能笼统地把“任何有评分”算作喜欢。

用户反馈：

1. 网页“我的最爱”没有发布到 Plex，导致 Plex/Plexamp 中不能直接打开网页所见的同一份收藏。
2. 新注册或首次进入的用户应默认看到一个固定的“我的最爱”入口，不需要自己创建。网页目前有固定入口，但它并不是 Plex 实体歌单；需要明确新用户在 Plex 端应看到什么。
3. 不应同时留下两份让用户困惑的“我的最爱”。用户原先在 Plex 创建的规则歌单只取五星，而网页视图取四星和五星；处理旧歌单时必须先辨明它是智能歌单还是普通歌单，不能自动删除用户数据。

爱心交互补充：播放器、歌曲列表和全库搜索统一使用更大的爱心；未喜欢时空心、悬停变红，点击后红色实心，再点取消。当前工作区已将图标调整为约 26px 并通过回归测试，尚未发布。旧 Plex 智能歌单的规则迁移尚未执行。

剩余实施边界：Plex 端需要使用可随评分自动变化的规则歌单；旧同名歌单只能在归属、曲库和旧规则均可验证时原位迁移。遇到普通同名歌单或多个候选时停止并提示，不删除或覆盖用户数据。

用户已明确档案单位：一个 Plex 用户加一个音乐曲库就是一个独立档案；同一 Plex 用户的“音乐”和“经典音乐”应各有自己的“我的最爱”，绝不跨曲库合并。网页固定入口与 Plex 端实体歌单都以这个档案为界，默认进入时建立或复用。评分口径不随档案改变，仍为 Plex 评分值至少 8。该边界已明确，不再向用户重复询问；实际实体歌单建立和旧规则迁移仍待实施、验证、发布。

## 导入外部歌单与曲库整理页面过于复杂

用户截图：导入页 `codex-clipboard-20376e65-9978-4734-9e4a-7a8c1d055f38.png`；曲库整理页 `codex-clipboard-71a54033-949e-4f0e-82cb-27874b7d5cbe.png`；运行详情 `codex-clipboard-b78cbc34-560a-4e79-953c-15ee39751fc8.png`。

- 导入页：整页和内部歌曲列表同时滚动，查看歌曲要来回切换两个滚动条；鼠标悬停时部分文字对比度不足甚至看不见；导入入口、已导入来源、匹配状态和歌曲详情层层堆叠。
- 导入页示意方向：一个明显的链接/文件导入入口，已导入来源压缩成单行，匹配状态用标签切换；歌曲列表只随整页滚动，没有内部滚动框；歌曲名及操作在悬停时保持可读。
- 曲库整理页：页面标题重复，自动整理、检查新歌、授权、统计、歌单维护和运行报告缺少层次；每行重复展示“停止维护”“移除歌单”，底部技术说明和地址干扰日常使用。
- 曲库整理页示意方向：只保留一个主标题；把“检查新歌曲”作为主操作，自动整理开关与时间放一行，统计压成一条；分类歌单列表保留“打开”，低频操作进入每行“更多”；报告默认收起，错误时再提示。
- 两页静态示意图已给用户审阅；只是视觉方向，尚未获得用户对实施细节的确认。
- 示意图补充反馈（`codex-clipboard-33c9496c-0c68-4638-a724-bbbcf4bed6c1.png`）：第一版导入页漏掉关键的“创建／更新 Plex 歌单”区，包括歌单名称、曲库整理时自动刷新、更新 Plex 歌单按钮，也未明确展示缺失歌曲的复制与导出功能。新版导入页示意图已补齐这些功能；页面精简不能以删除原有核心能力为代价。
