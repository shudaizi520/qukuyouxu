# TrueNAS SCALE 安装

曲库有序在 TrueNAS 上使用与普通 Docker 完全相同的镜像，不再维护一份不断增长的专用 YAML。

在 TrueNAS 的“自定义应用”中使用正式镜像 `ghcr.io/shudaizi520/qukuyouxu:latest`，并设置：

- 容器端口：`9511`
- 主机端口：`9511`，或选择一个未占用端口
- 持久目录：容器内 `/data`
- 环境变量 `PORT=9511`
- 环境变量 `DATA_ROOT=/data`
- 重启策略：`unless-stopped`

`latest` 始终指向最新正式版。以后 GitHub 发布新版本后，TrueNAS 会检测到同一标签的镜像摘要变化；在已安装应用右侧点“更新”即可拉取新版。已经使用 `:2.0.6` 等固定版本标签的用户，只需在编辑应用时改成 `:latest` 一次。

镜像使用固定的非 root 身份 `UID 10001 / GID 10001`。创建宿主机数据集后，在 TrueNAS ACL 中给用户 ID `10001` 和组 ID `10001` 对该数据集的修改权限，再挂载到 `/data`。不要使用 `chmod 777`。首次启动后如果页面无法保存设置，先检查这一项。

不要把 Plex Token 或 QQ Cookie 直接写在应用 YAML 中；首次启动后通过网页完成授权。

首次打开网页时，直接填写管理员用户名和两遍密码建立账户。若前面还有 HTTPS 反向代理，请把 `PUBLIC_ORIGIN` 环境变量设为浏览器实际访问的完整地址；使用非默认端口时也要写上端口，例如 `https://music.example.com:9981`。不要填反代后端的局域网地址。

反代需要保留原始 `Host`，并让 `/api/`、`/static/`、音频 `Range` 请求直通，不要缓存登录响应。请使用独立域名的根路径；完整的 [HTTPS 反代检查清单](docker.md#https-反向代理) 也适用于 TrueNAS。应用页面资源由容器自身提供，不依赖国外 CDN；Plex 官方授权需要连接 Plex 网站时，可改用局域网 Plex 地址与 Token 手动连接。

从旧版迁移时，先在不同端口启动新容器，导入并校验歌曲缓存，确认页面和 Plex 连接正常后再切换正式端口。旧应用和旧数据库在验收完成前保持不动。

完整备份时先停止应用，在 TrueNAS 数据集页面创建只读快照，或复制整个 `/data` 数据集。恢复应写入一个新数据集并保留原快照；确认新实例健康后再切换端口。只迁移耗时的歌曲缓存时，在旧容器中使用 `qukuyouxu-cache export`，将归档下载到私有目录，再复制到新容器执行 `qukuyouxu-cache import`。
