# 发布流程

曲库有序使用语义化版本和不可变容器标签。只有形如 `v1.2.3` 的 Git 标签会触发公开镜像构建。

发布前必须确认：

1. 仓库检查没有数据库、凭据、日志、补丁载荷或历史升级 YAML。
2. Python 编译检查和完整测试通过。
3. 歌曲缓存完成一次导出、校验、空数据库导入的往返测试。
4. 本地或测试主机上的容器健康检查通过。
5. `CHANGELOG.md` 已说明用户可见的变化和升级注意事项。
6. 已记录当前稳定镜像标签，能够直接回滚。
7. `requirements.lock` 已提交，发布标签必须与 `helper.__version__` 完全一致。

GitHub Actions 会先执行隐私检查、依赖检查、编译和测试，再核对标签版本，最后构建 `linux/amd64` 与 `linux/arm64` 镜像并生成来源证明和软件物料清单。不要手工覆盖已经发布的版本标签。
